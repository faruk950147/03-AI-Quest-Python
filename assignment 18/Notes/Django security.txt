# Django Security — গুরুত্বপূর্ণ বিষয়সমূহ 🔐

Django একটি security-focused web framework। এটি অনেক common web security problem থেকে application-কে রক্ষা করার জন্য built-in security features এবং recommended settings প্রদান করে।

---

## 1. Cross-Site Scripting (XSS) Protection

### XSS কী?

**Cross-Site Scripting (XSS)** হলো এমন একটি attack যেখানে attacker কোনো web page-এর মাধ্যমে malicious HTML বা JavaScript অন্য user-এর browser-এ execute করানোর চেষ্টা করে।

উদাহরণ:

```html
<script>
    alert("Hacked");
</script>
```

ধরা যাক, কোনো user এই malicious content database-এ save করল।

### Django কীভাবে XSS থেকে রক্ষা করে?

Django template system সাধারণভাবে variable output-এর HTML special characters automatically escape করে।

```django
{{ username }}
```

যদি `username` হয়:

```html
<script>alert("Hacked")</script>
```

তাহলে browser এটিকে JavaScript হিসেবে execute না করে escaped text হিসেবে দেখবে।

উদাহরণ:

```html
&lt;script&gt;alert("Hacked")&lt;/script&gt;
```

### `safe` filter-এর ব্যাপারে সতর্কতা

```django
{{ username|safe }}
```

`safe` ব্যবহার করলে Django ওই value-কে আর HTML-escaped করবে না।

তাই **untrusted user input-এর ক্ষেত্রে `safe` ব্যবহার করা উচিত নয়**।

> `safe` ব্যবহার করার আগে নিশ্চিত হতে হবে যে contentটি trusted এবং properly sanitized।

### গুরুত্বপূর্ণ কথা

Django-এর automatic escaping XSS-এর বিরুদ্ধে একটি গুরুত্বপূর্ণ protection, কিন্তু developer-এর ভুল HTML/JavaScript handling থেকেও XSS vulnerability তৈরি হতে পারে।

# 2. Cross-Site Request Forgery (CSRF) Protection

## CSRF কী?

**Cross-Site Request Forgery (CSRF)** হলো এমন একটি attack যেখানে attacker logged-in user's browser ব্যবহার করে এমন একটি unwanted request পাঠানোর চেষ্টা করে, যা user নিজে উদ্দেশ্য করে করেনি।

উদাহরণ:

User কোনো website-এ login করা অবস্থায় আছে।

Attacker এমন একটি malicious page তৈরি করল:

```html
<form action="https://example.com/change-email/" method="POST">
    <input type="hidden" name="email" value="attacker@example.com">
</form>
```

User-এর browser থেকে request পাঠানোর চেষ্টা হতে পারে।

## Django-এর Solution

Django CSRF protection-এর জন্য **CSRF token** ব্যবহার করে।

Template form:

```html
<form method="post">
    {% csrf_token %}

    <input type="text" name="name">

    <button type="submit">
        Submit
    </button>
</form>
```

Django-এর CSRF middleware request-এর token যাচাই করে।

### Important

`POST`, `PUT`, `PATCH`, `DELETE` ধরনের state-changing request-এর ক্ষেত্রে CSRF protection সঠিকভাবে configure/use করা গুরুত্বপূর্ণ।

# 3. SQL Injection Protection

## SQL Injection কী?

SQL Injection হলো এমন একটি attack যেখানে attacker application-এর SQL query-এর structure manipulate করার চেষ্টা করে।

### Bad Example

```python
query = "SELECT * FROM users WHERE name='%s'" % username
```

এভাবে user input সরাসরি SQL string-এর মধ্যে বসানো নিরাপদ নয়।

### Django ORM ব্যবহার

Django ORM সাধারণত parameterized queries ব্যবহার করে:

```python
User.objects.filter(username=username)
```

এখানে user input সরাসরি SQL string-এর অংশ হিসেবে concatenate করা হচ্ছে না।

### Important

Django ORM SQL Injection-এর ঝুঁকি অনেক কমায়, কিন্তু developer যদি raw SQL ব্যবহার করেন তাহলে সতর্ক হতে হবে।

উদাহরণ:

```python
from django.db import connection
```

Raw SQL ব্যবহার করার সময় parameterization ব্যবহার করা উচিত।

### মনে রাখবেন

**ORM ব্যবহার করা = automatically সব SQL-related security problem solved নয়।**

Developer-এর raw SQL, dynamic SQL এবং unsafe query construction-এর উপরও security নির্ভর করে।

# 4. Clickjacking Protection

## Clickjacking কী?

Clickjacking হলো এমন একটি attack যেখানে attacker কোনো trusted website-কে অন্য webpage-এর মধ্যে, যেমন `iframe`-এর ভিতরে load করে user-কে এমন কিছু click করানোর চেষ্টা করে যা user বুঝতে পারে না।

## Django Protection

Django-তে clickjacking protection-এর জন্য `X-Frame-Options` header ব্যবহার করা যায়।

### DENY

```python
X_FRAME_OPTIONS = "DENY"
```

এর অর্থ হলো site-টি কোনো iframe-এর ভিতরে load করা যাবে না।

### SAMEORIGIN

```python
X_FRAME_OPTIONS = "SAMEORIGIN"
```

এর অর্থ হলো একই origin-এর page থেকে iframe-এ load করার অনুমতি দেওয়া হতে পারে।

### কোনটি ব্যবহার করবেন?

Application-এর প্রয়োজন অনুযায়ী নির্বাচন করতে হবে।

যদি iframe-এর প্রয়োজন না থাকে, সাধারণভাবে:

```python
X_FRAME_OPTIONS = "DENY"
```

ব্যবহার করা যায়।

# 5. SSL / HTTPS

## HTTPS কী?

HTTPS browser এবং server-এর মধ্যে communication encrypt করে।

এর ফলে network-এর মাঝখানে থাকা attacker-এর পক্ষে transmitted data সহজে পড়া বা পরিবর্তন করা কঠিন হয়।

## Django Setting

Production application-এ HTTP request-কে HTTPS-এ redirect করতে:

```python
SECURE_SSL_REDIRECT = True
```

ব্যবহার করা যায়।

### গুরুত্বপূর্ণ

শুধু এই setting দিলেই সম্পূর্ণ HTTPS security নিশ্চিত হয় না।

Production environment-এ সাধারণত আরও বিষয় configure করতে হয়, যেমন:

```python
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
```

এবং deployment-এর সময় সঠিক proxy/load balancer এবং HTTPS configuration নিশ্চিত করতে হয়।

---

# 6. Host Header Validation

## Host Header কী?

HTTP request-এ একটি `Host` header থাকে।

উদাহরণ:

```http
Host: example.com
```

যদি application যেকোনো host গ্রহণ করে, তাহলে কিছু ধরনের Host Header-related attack-এর ঝুঁকি তৈরি হতে পারে।

## Django Protection

Django-তে `ALLOWED_HOSTS` ব্যবহার করা হয়।

```python
ALLOWED_HOSTS = [
    "example.com",
    "www.example.com",
]
```

এর মাধ্যমে Django নির্দিষ্ট allowed host name গ্রহণ করে।

### Development

Development environment-এ কখনো দেখা যায়:

```python
ALLOWED_HOSTS = ["localhost", "127.0.0.1"]
```

Production-এ প্রয়োজন অনুযায়ী নির্দিষ্ট domain ব্যবহার করা ভালো।

---

# 7. Referrer Policy

## Referrer কী?

Browser যখন একটি webpage থেকে অন্য resource বা website-এ request পাঠায়, তখন কিছু ক্ষেত্রে আগের page-এর URL-এর information `Referer` header-এর মাধ্যমে পাঠাতে পারে।

এই information-এর মধ্যে sensitive URL information থাকতে পারে।

## Django Setting

Django-তে Referrer Policy configure করা যায়:

```python
SECURE_REFERRER_POLICY = "same-origin"
```

এর অর্থ হলো একই origin-এর request-এর ক্ষেত্রে referrer information পাঠানোর policy বজায় থাকে, আর cross-origin request-এ policy অনুযায়ী তা সীমিত করা হয়।

### অন্য policy

প্রয়োজন অনুযায়ী ব্যবহার করা যেতে পারে:

```python
SECURE_REFERRER_POLICY = "strict-origin-when-cross-origin"
```

Security এবং privacy requirement অনুযায়ী policy নির্বাচন করা উচিত।

# 8. Session Security

User login করার পর Django session ব্যবহার করে user-এর authentication state ধরে রাখতে পারে।

Session cookie secure রাখা গুরুত্বপূর্ণ।

## গুরুত্বপূর্ণ Settings

### 1. Secure Cookie

```python
SESSION_COOKIE_SECURE = True
```

এর অর্থ session cookie HTTPS connection-এর মাধ্যমে পাঠানো হবে।

### 2. HttpOnly Cookie

```python
SESSION_COOKIE_HTTPONLY = True
```

এর ফলে সাধারণ JavaScript code থেকে session cookie access করা যায় না।

এটি cookie theft-এর কিছু client-side risk কমাতে সাহায্য করে।

### 3. Browser বন্ধ হলে Session Expire

```python
SESSION_EXPIRE_AT_BROWSER_CLOSE = True
```

এটি browser session শেষ হলে session cookie expire করার behavior configure করে।

### Important

`SESSION_EXPIRE_AT_BROWSER_CLOSE = True` সব security problem solve করে না। Authentication/session security-এর জন্য strong passwords, HTTPS, secure cookies এবং appropriate session management গুরুত্বপূর্ণ।

---

# 9. User Uploaded Content Security

User যদি application-এ file upload করতে পারে, তাহলে security risk তৈরি হতে পারে।

উদাহরণ:

* Malicious file
* খুব বড় file
* Unexpected file type
* Dangerous content
* Storage abuse
* Filename-related সমস্যা

## File Upload-এর সময় কী করবেন?

### 1. File Type Validation

Django validator ব্যবহার করা যায়।

```python
from django.core.validators import FileExtensionValidator

file = models.FileField(
    upload_to="documents/",
    validators=[
        FileExtensionValidator(
            allowed_extensions=["jpg", "png", "pdf"]
        )
    ]
)
```

### গুরুত্বপূর্ণ

শুধু file extension check করলেই সবসময় নিরাপত্তা নিশ্চিত হয় না।

কারণ কেউ malicious file-এর extension পরিবর্তন করতে পারে।

তাই sensitive application-এ file content/type আরও carefully validate করা প্রয়োজন।

---

## 2. File Size Limit

User যেন unlimited বড় file upload করতে না পারে, তার জন্য size limit রাখা উচিত।

Application এবং infrastructure level-এ upload size limit configure করা যায়।

---

## 3. Media Files আলাদাভাবে Handle করা

User-uploaded files সাধারণত media storage-এ রাখা হয়।

```text
media/
    images/
    documents/
    uploads/
```

Production environment-এ user-uploaded content serve করার architecture carefully design করা উচিত।

বিশেষ করে executable বা server-side code হিসেবে user-uploaded file execute হওয়ার সুযোগ রাখা যাবে না।

# 10. Django Security Middleware

Django-এর security features-এর একটি গুরুত্বপূর্ণ অংশ হলো middleware।

উদাহরণ:

```python
MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
]
```

এর মধ্যে:

### `SecurityMiddleware`

Security-related কিছু HTTP behavior এবং security settings apply করতে সাহায্য করে।

### `CsrfViewMiddleware`

CSRF protection-এর জন্য গুরুত্বপূর্ণ।

# 11. আরও কিছু গুরুত্বপূর্ণ Security Settings

Production Django project-এ নিচের settings-গুলোও গুরুত্বপূর্ণ হতে পারে।

### HSTS

HTTPS ব্যবহারে browser-কে আরও strongly নির্দেশ দিতে:

```python
SECURE_HSTS_SECONDS = 31536000
```

প্রয়োজন অনুযায়ী:

```python
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
```

> HSTS enable করার আগে domain এবং HTTPS configuration সঠিকভাবে কাজ করছে কিনা নিশ্চিত হওয়া জরুরি।

---

## CSRF Cookie Secure

```python
CSRF_COOKIE_SECURE = True
```

HTTPS ব্যবহারের ক্ষেত্রে CSRF cookie-কে secure করার জন্য ব্যবহার করা যায়।

---

## Content Type Sniffing Protection

```python
SECURE_CONTENT_TYPE_NOSNIFF = True
```

এটি browser-এর MIME type sniffing behavior সীমিত করতে সাহায্য করে।

# Interview Questions

### 1. What is XSS?

XSS is an attack where malicious script or HTML is injected into a webpage and executed in another user's browser.

### 2. How does Django protect against XSS?

Django templates automatically escape variable output by default.

### 3. What is CSRF?

CSRF is an attack where an attacker attempts to make an authenticated user's browser send an unwanted state-changing request.

### 4. How does Django protect against CSRF?

Django uses CSRF tokens and CSRF middleware.

### 5. What is SQL Injection?

SQL Injection is an attack where malicious input manipulates the structure of a SQL query.

### 6. Does Django ORM help prevent SQL Injection?

Yes. Django ORM normally uses parameterized queries, but unsafe raw SQL can still introduce vulnerabilities.

### 7. What is Clickjacking?

Clickjacking tricks users into interacting with a webpage or action through a deceptive frame or interface.

### 8. What is `ALLOWED_HOSTS`?

`ALLOWED_HOSTS` defines which host/domain names Django will accept for incoming HTTP requests.

### 9. What does `SESSION_COOKIE_SECURE` do?

It makes the session cookie available only over HTTPS connections.

### 10. Why is `SESSION_COOKIE_HTTPONLY` useful?

It prevents normal client-side JavaScript from reading the session cookie.
