# Django Middleware — Complete Beginner to Advanced Notes

---

# 1. Django Middleware কী?

**Middleware** হলো Django-এর request/response processing-এর একটি layer, যা request view-এ পৌঁছানোর আগে এবং response client-এর কাছে যাওয়ার আগে processing করতে পারে।

সহজভাবে:

```text
Browser
   ↓
Request
   ↓
Middleware
   ↓
URL Resolver
   ↓
View
   ↓
Middleware
   ↓
Response
   ↓
Browser
```

Middleware দিয়ে application-wide কাজ করা যায়, যেমন:

```text
Authentication
Logging
Security
Request tracking
Rate limiting
Custom headers
Maintenance mode
Multi-tenancy
```

---

# 2. Middleware কোথায় Configure করা হয়?

Django project-এর:

```text

```

```python
MIDDLEWARE = [

    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",

]
```

এগুলো Django-এর built-in middleware।

# 9. Custom Middleware তৈরি করা

ধরি, আমরা প্রতিটি request-এর সময় একটি message print করতে চাই।

Project structure:

```text
project/
│
├── manage.py
│
├── myproject/
│   └── settings.py
│
└── myapp/
    ├── middleware.py
    └── views.py
```

`middleware.py`:

```python
class MyMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        print("Request received")

        response = self.get_response(request)

        print("Response sent")

        return response
```

```python
def __init__(self, get_response):
```

এখানে সাধারণত:

```text
Configuration

Middleware setup
```

Important:

> `__init__()` সাধারণত প্রতিটি request-এর জন্য call হয় না। Middleware instance তৈরি হওয়ার সময় initialize করা হয়।

# 11. Middleware `__call__()`

`__call__()` হলো custom middleware-এর সবচেয়ে গুরুত্বপূর্ণ method।

```python
def __call__(self, request):

    print("Before view")

    response = self.get_response(request)

    print("After view")

    return response
```

এখানে:

```python
self.get_response(request)
```

পরবর্তী middleware বা শেষ পর্যন্ত view-এর দিকে request পাঠায়।

তারপর response ফিরে আসে।

# 12. Middleware Onion Model

Django middleware-কে **onion-like layer** হিসেবে ভাবা যায়।

ধরি:

```text
Middleware 1
Middleware 2
Middleware 3
View
```

Request-এর সময়:

```text
Request
   ↓
Middleware 1
   ↓
Middleware 2
   ↓
Middleware 3
   ↓
View
```

Response ফেরার সময়:

```text
View
   ↓
Middleware 3
   ↓
Middleware 2
   ↓
Middleware 1
   ↓
Response
```

অর্থাৎ outer middleware-এর code view-এর আগে এবং পরে দুই phase-এই কাজ করতে পারে।

# 13. Middleware Execution Order

`settings.py`-এর:

```python
MIDDLEWARE = [
    ...
]
```

list-এর order গুরুত্বপূর্ণ।

সাধারণভাবে request phase-এ middleware উপর থেকে নিচের দিকে প্রবেশ করে।

Response phase-এ middleware layer উল্টো দিকে ফিরে আসে।

```text
Request
   ↓
M1
   ↓
M2
   ↓
M3
   ↓
View
   ↑
M3
   ↑
M2
   ↑
M1
   ↑
Response
```

# 14. Middleware Short-Circuit

Middleware চাইলে request-কে view পর্যন্ত যেতে না দিয়ে সরাসরি response return করতে পারে।

Example:

```python
from django.http import HttpResponse


class MaintenanceMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        maintenance = True

        if maintenance:
            return HttpResponse(
                "Site under maintenance"
            )

        return self.get_response(request)
```

Flow:

```text
Request
   ↓
Middleware
   ↓
Maintenance?
   │
   ├── Yes → Response
   │
   └── No
        ↓
      View
```

এক্ষেত্রে view execute হবে না।

# 15. Middleware Hooks

Django middleware-এ প্রধানভাবে দুই ধরনের বিষয় বুঝতে হবে:

### Modern middleware style

```text
__init__()
__call__()
```

### Optional middleware hooks / `MiddlewareMixin`

```text
process_view()
process_exception()
process_template_response()
```

`process_request()` এবং `process_response()`-এর মতো old-style hook support করতে সাধারণত `MiddlewareMixin` ব্যবহার করা হয়।

---

# 16. `process_view()`

`process_view()` view execute হওয়ার আগে call হয়।

এটি সাধারণত `MiddlewareMixin`-এর মাধ্যমে ব্যবহৃত হয়।

Example:

```python
from django.utils.deprecation import MiddlewareMixin


class ViewMiddleware(MiddlewareMixin):

    def process_view(
        self,
        request,
        view_func,
        view_args,
        view_kwargs,
    ):
        print(
            "View:",
            view_func.__name__,
        )
```

Parameters:

| Parameter     | Meaning              |
| ------------- | -------------------- |
| `request`     | Current request      |
| `view_func`   | যে view call হবে     |
| `view_args`   | Positional arguments |
| `view_kwargs` | Keyword arguments    |

---

# 17. `process_view()` কখন ব্যবহার করবেন?

Common examples:

```text
Permission checks
```

# 18. `process_exception()`

View বা downstream processing-এর সময় exception হলে এই hook ব্যবহার করা যায়।

Example:

```python
from django.utils.deprecation import MiddlewareMixin


class ExceptionMiddleware(MiddlewareMixin):

    def process_exception(
        self,
        request,
        exception,
    ):
        print(
            "Exception:",
            exception,
        )
```

ব্যবহার:

```text
Error logging
Monitoring
Custom exception handling
```

---

# 19. `process_template_response()`

যখন view একটি `TemplateResponse` return করে, তখন এই hook ব্যবহার করা যায়।

Example:

```python
from django.utils.deprecation import MiddlewareMixin


class TemplateMiddleware(MiddlewareMixin):

    def process_template_response(
        self,
        request,
        response,
    ):
        response.context_data["site_name"] = (
            "My Website"
        )

        return response
```

### Important

এটি **সব ধরনের response-এর ক্ষেত্রে run করে না**।

এটি specifically `TemplateResponse`-এর মতো response-এর ক্ষেত্রে ব্যবহৃত হয়।

---

# 20. `process_request()` এবং `process_response()`

`MiddlewareMixin` ব্যবহার করলে পুরোনো-style hooks ব্যবহার করা যায়।

Example:

```python
from django.utils.deprecation import MiddlewareMixin


class MyMiddleware(MiddlewareMixin):

    def process_request(self, request):
        print("Before view")

    def process_response(self, request, response):
        print("After view")

        return response
```

তবে নতুন custom middleware লেখার ক্ষেত্রে সাধারণত modern `__call__()` style বোঝা এবং ব্যবহার করা বেশি গুরুত্বপূর্ণ।

---

# 21. Middleware Hooks Summary

| Method                        | Purpose                        |
| ----------------------------- | ------------------------------ |
| `__init__()`                  | Middleware initialization      |
| `__call__()`                  | Main request/response wrapper  |
| `process_request()`           | Request processing before view |
| `process_view()`              | View execution-এর আগে          |
| `process_exception()`         | Exception handling             |
| `process_template_response()` | `TemplateResponse` processing  |
| `process_response()`          | Response processing            |

> `process_*` methods-এর behavior middleware implementation/order-এর ওপর নির্ভর করে। `__call__()` modern middleware-এর core mechanism।

# 22. Request Logging Middleware

একটি simple logging middleware:

```python
import logging


logger = logging.getLogger(__name__)


class LoggingMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        logger.info(
            "%s %s",
            request.method,
            request.path,
        )

        response = self.get_response(request)

        logger.info(
            "Status: %s",
            response.status_code,
        )

        return response
```

`print()`-এর বদলে production application-এ Python `logging` ব্যবহার করা বেশি appropriate।

# 23. Request Time Measurement

Request process হতে কত সময় লাগছে তা measure করতে:

```python
import time


class TimerMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        start = time.perf_counter()

        response = self.get_response(request)

        duration = (
            time.perf_counter() - start
        )

        print(
            f"{request.path}: "
            f"{duration:.4f}s"
        )

        return response
```

ব্যবহার:

```text
Performance monitoring
Slow endpoint detection
Debugging
```

# 25. IP Blocking Middleware

Simple example:

```python
from django.http import HttpResponse


class BlockIPMiddleware:

    BLOCKED_IPS = {
        "192.168.1.10",
    }

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        ip = request.META.get(
            "REMOTE_ADDR"
        )

        if ip in self.BLOCKED_IPS:
            return HttpResponse(
                "Access Denied",
                status=403,
            )

        return self.get_response(request)
```

### Important

Production environment-এ proxy/load balancer-এর কারণে `REMOTE_ADDR` সবসময় actual client IP নাও হতে পারে।

তাই forwarded IP headers blindly trust করা উচিত নয়।

# 26. Authentication / Login Check Middleware

একটি simple example:

```python
from django.shortcuts import redirect


class LoginRequiredMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        public_paths = {
            "/login/",
            "/register/",
        }

        if (
            not request.user.is_authenticated
            and request.path not in public_paths
        ):
            return redirect("login")

        return self.get_response(request)
```

### Important

Real project-এ Django-এর built-in authentication tools এবং `login_required` / `LoginRequiredMixin` অনেক ক্ষেত্রে বেশি appropriate।

Global middleware দিয়ে login protection করলে admin, login, static/media, API এবং public pages-এর মতো exception carefully handle করতে হয়।

# 27. API Authentication Middleware

Middleware দিয়ে token/API-key check করা technically সম্ভব।

Example:

```python
from django.http import JsonResponse


class APIKeyMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        api_key = request.headers.get(
            "X-API-Key"
        )

        if request.path.startswith("/api/"):

            if api_key != "expected-key":
                return JsonResponse(
                    {
                        "error": "Invalid API key"
                    },
                    status=401,
                )

        return self.get_response(request)
```

### Important

Real application-এ API key hard-code করা উচিত নয়।

Use:

```text
Environment variables
Secret management
Database-backed credentials
```

যেখানে appropriate।

# 32. Middleware vs Decorator vs Signals

| Feature    | Middleware                 | Decorator              | Signal                   |
| ---------- | -------------------------- | ---------------------- | ------------------------ |
| Scope      | Global/request-level       | Specific view/function | Event-based              |
| Trigger    | Request/response lifecycle | Function/view call     | Specific event           |
| Common use | Logging, security          | View-specific behavior | Model/application events |
| Example    | Request logging            | `login_required`       | `post_save`              |

# 34. Decorator Example

নির্দিষ্ট view-এর জন্য:

```python
from functools import wraps


def my_decorator(view_func):

    @wraps(view_func)
    def wrapper(
        request,
        *args,
        **kwargs,
    ):
        print("Before view")

        return view_func(
            request,
            *args,
            **kwargs,
        )

    return wrapper
```

ব্যবহার:

```python
@my_decorator
def home(request):
    ...
```

# 35. Signal Example

Model event-এর সঙ্গে কাজ করার জন্য:

```python
from django.db.models.signals import post_save
from django.dispatch import receiver

from .models import Product


@receiver(
    post_save,
    sender=Product,
)
def product_created(
    sender,
    instance,
    created,
    **kwargs,
):
    if created:
        print(
            "New product:",
            instance.name,
        )
```

এখানে Product save হলে signal handler execute করতে পারে।

# 36. Middleware vs Decorator vs Signal — Easy Rule

মনে রাখুন:

```text
Middleware
→ Request/Response level

Decorator
→ Specific function/view level

Signal
→ Event level
```

Example:

```text
সব request log করতে চাই
→ Middleware

শুধু checkout view protect করতে চাই
→ Decorator

Product create হলে কিছু করতে চাই
→ Signal
```

# 37. Async Middleware

Modern Django asynchronous middleware support করে।

Example:

```python
class AsyncMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    async def __call__(self, request):

        print("Before view")

        response = await self.get_response(
            request

        print("After view")

        return response
```

### Important

Performance benefit নির্ভর করে:

```text

```

এর ওপর।

# 39. Production-Level Logging Middleware

Production environment-এ `print()`-এর পরিবর্তে `logging` ব্যবহার করা উচিত।

```python
import logging
import time


logger = logging.getLogger(__name__)


class LoggingMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        start = time.perf_counter()

        response = self.get_response(request)

        duration = (
            time.perf_counter() - start
        )

        logger.info(
            "%s %s %s %.3fs",
            request.method,
            request.path,
            response.status_code,
            duration,
        )

        return response
```

Example log:

```text
GET /products/ 200 0.320s
POST /checkout/ 201 0.850s
```

# 41. Custom Security Headers

Response-এ security-related headers যোগ করা যায়।

Example:

```python
class SecurityHeadersMiddleware:

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):

        response = self.get_response(request)

        response["X-Frame-Options"] = "DENY"
        response["X-Content-Type-Options"] = "nosniff"

        return response
```

তবে security headers manually add করার আগে Django-এর built-in security settings এবং existing middleware-এর configuration বোঝা উচিত।

### Important correction

পুরোনো:

```text
X-XSS-Protection
```

header-কে modern browser security-এর primary protection হিসেবে ধরা উচিত নয়। Modern applications-এ Content Security Policy (CSP), proper output escaping এবং অন্যান্য security controls বেশি গুরুত্বপূর্ণ।

# 44. Middleware-এ গুরুত্বপূর্ণ বিষয়

## 1. Order Matters

```python
MIDDLEWARE = [
    "middleware_a",
    "middleware_b",
]
```

`middleware_a` outer layer হিসেবে কাজ করে এবং `middleware_b` তার ভিতরের layer হিসেবে কাজ করে।

## 2. সব কাজ Middleware-এ করা উচিত নয়

Business logic সাধারণত middleware-এর মধ্যে রাখা উচিত নয়।

Bad example:

```text
Order calculation
Payment processing
Complex business rules
```

এগুলো সাধারণত service/view/domain layer-এ রাখা ভালো।

Middleware-এর কাজ হওয়া উচিত cross-cutting concerns handle করা।

# 49. Interview Questions

## Q1. Django Middleware কী?

**Answer:**

Middleware is a layer in Django's request/response processing system that can process a request before it reaches the view and process the response before it reaches the client.

---

## Q2. Middleware কোথায় configure করা হয়?

```text
settings.py
```

এর:

```python
MIDDLEWARE
```

list-এ।

---

## Q3. Middleware-এর প্রধান method কী?

Modern middleware-এর core methods:

```python
__init__()
__call__()
```

---

## Q4. `__init__()` কখন execute হয়?

Middleware instance initialize হওয়ার সময়।

---

## Q5. `__call__()` কখন execute হয়?

প্রতিটি request-এর processing-এর সময়।

---

## Q6. `process_view()` কী?

View execute হওয়ার আগে middleware hook হিসেবে কাজ করে।

---

## Q7. `process_exception()` কী?

View/downstream processing-এর সময় exception হলে exception handling hook হিসেবে ব্যবহার করা যায়।

---

## Q8. `process_template_response()` কী?

`TemplateResponse`-এর মতো response return হলে response processing-এর জন্য ব্যবহার করা যায়।

---

## Q9. Middleware কি request block করতে পারে?

হ্যাঁ।

Middleware সরাসরি response return করলে request আর view পর্যন্ত যেতে পারে না।

---

## Q10. Middleware vs Decorator?

```text
Middleware
→ Global/request-level

Decorator
→ Specific view/function
```

---

## Q11. Middleware vs Signal?

```text
Middleware
→ Request/response lifecycle

Signal
→ Event-driven behavior
```

---

## Q12. Middleware-এর execution order কেমন?

Request:

```text

```

```text

```

# One-Line Definitions

```text
Middleware
→ Django request/response lifecycle-এর একটি processing layer।

__init__()
→ Middleware initialize করে।

__call__()
→ Request এবং response-এর মূল processing wrapper।

process_view()
→ View execute হওয়ার আগে hook হিসেবে কাজ করে।

process_exception()
→ Exception হলে handling/logging-এর জন্য ব্যবহৃত হয়।

process_template_response()
→ TemplateResponse processing-এর জন্য ব্যবহৃত হয়।

MiddlewareMixin
→ Legacy-style process_* middleware hooks ব্যবহারের সুবিধা দেয়।

Decorator
→ নির্দিষ্ট view/function-এর behavior পরিবর্তন করে।

Signal
→ নির্দিষ্ট event ঘটলে handler execute করে।

ASGI
→ Async-capable Python web applications ও protocols-এর interface।

Channels
→ Django-তে WebSocket এবং অন্যান্য asynchronous communication use case handle করার framework।

Redis
→ Channels-এর জন্য common shared channel-layer backend।
```

# Final Rule to Remember

```text
Global Request/Response Concern
        ↓
    Middleware

Specific View Concern
        ↓
     Decorator

Specific Application Event
        ↓
      Signal
```
